## 第一组：C# 语言基础

### 1. 抽象类和接口的区别是什么

你项目里的对应位置：

- `ModbusDeviceAttribute` 是抽象类
- `IDeviceModel`、`IPointAtrributesCache` 是接口

你要会回答：

- 抽象类适合承载“共有字段/共有默认结构”
- 接口适合承载“约定”
- 一个类型可以实现多个接口，但只能继承一个基类

### 2. 结构体和类的区别是什么

你项目里的对应位置：

- `RegisterCache`
- `CoilCache`

你要会回答：

- 结构体是值类型
- 类是引用类型
- 值类型复制会拷贝整个值
- 如果结构体语义不稳定、字段较多、需要多态，往往更适合改成类

### 3. 委托、匿名方法、Lambda 的关系是什么

你项目里的对应位置：

- `Program.cs` 的 `SpecialDelegates`

你要会回答：

- 委托是类型
- 匿名方法和 Lambda 是创建委托实例的语法形式
- Lambda 更现代、更简洁

## 第二组：Attribute 与反射

### 4. 为什么设备点位适合用 Attribute 声明

你要会回答：

- 因为它把地址、拼接方式、映射元数据贴在属性声明上
- 这样设备定义更集中
- Runtime 可以统一扫描，不必每个设备单独写硬编码读取逻辑

### 5. 反射适合在哪个阶段做

你项目里的对应位置：

- `DataMapper` 构造函数
- 后来的 Runtime 构造阶段

你要会回答：

- 适合在初始化阶段做一次
- 不适合每次轮询都重新扫描
- 因为反射有成本，且元数据通常是稳定的

### 6. Attribute 里应该放多少行为

你要会回答：

- 教学期可以放少量行为
- 工业期更推荐 Attribute 表达元数据
- 具体解释逻辑交给 Runtime 或 Mapper

## 第三组：工业通信与 Modbus

### 7. 寄存器和线圈的区别是什么

你要会回答：

- 寄存器通常承载数值型数据
- 线圈通常承载布尔型状态
- 两者在读取函数、地址含义、映射方式上都不同

### 8. 为什么 32 位值会涉及大小端拼接

你项目里的对应位置：

- `jointTypes.BigEndian32`
- `jointTypes.LittleEndian32`

你要会回答：

- Modbus 基本单位是 16 位寄存器
- 32 位值要由两个寄存器拼出来
- 不同设备厂商的高低字顺序可能不同

### 9. 自定义拼接为什么难

你项目里的对应位置：

- `IDeviceModel.TryJoint(...)`

你要会回答：

- 因为不是所有设备都遵守统一拼接规则
- 有些值需要设备级业务知识才能解释
- 所以要为“通用拼接失败时交给设备自己处理”预留入口

## 第四组：分层与架构

### 10. 为什么映射层和通信层要分开

你要会回答：

- 通信层负责把数据拿回来
- 映射层负责把数据解释成业务值
- 分开后更容易测试、复用和替换

### 11. 为什么 GUI 不应该直接操作串口

你要会回答：

- GUI 应该面向状态和结果，不应该面向底层资源
- 否则界面层会和通信细节耦合
- 也会让测试和维护非常困难

### 12. 为什么 Mission 和 Scheduler 适合拆成两层

你要会回答：

- Mission 更靠近资源和执行
- Scheduler 更靠近应用层和状态协调
- 这样 GUI 或上层调用者就不必直接理解串口和任务细节

## 第五组：异步、任务与生命周期

### 13. `Task` 是不是线程

你要会回答：

- 不是
- `Task` 是异步操作的抽象
- 它可能在线程池线程执行，也可能不是

### 14. `CancellationTokenSource` 的意义是什么

你要会回答：

- 它不是“强制杀线程”
- 它是“发出取消请求”
- 真正的执行代码必须主动检查取消令牌并配合退出

### 15. 为什么启动、停止、释放必须分开

你要会回答：

- 启动是进入工作状态
- 停止是结束当前工作流程
- 释放是回收资源并禁止继续使用
- 这三者语义不同，不能混成一个动作

## 第六组：工业级代码质量

### 16. 工业代码为什么讨厌 `Console.WriteLine` 到处都是

你要会回答：

- 因为不可分级
- 不易关闭
- 不利于收集与检索
- 正式项目更需要统一日志接口

### 17. 为什么“返回 bool”往往不够

你要会回答：

- 工业项目更关心失败原因
- 也关心部分成功和告警
- 所以通常需要结果对象或错误信息

### 18. 为什么状态枚举比多个 bool 更好

你要会回答：

- 多个 bool 容易出现矛盾状态
- 状态枚举更容易表达生命周期阶段
- 更方便日志、UI 和调试统一理解
