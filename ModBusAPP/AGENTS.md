# AGENTS.md

## 项目定位
这是一个“半学习、半开发”的 C# / WPF / Modbus 项目。
项目目标不只是完成功能，也包括帮助作者理解代码、积累知识、形成可以复盘的学习材料。

## 全局工作方式
- 修改代码时，优先兼顾“可运行、可阅读、可学习”。
- 如果同一问题有多种实现方式，优先选择更清晰、更容易讲明白的方案。
- 除了完成需求，也应尽量解释关键设计思路与实现原因。
- 当代码仍处于实验阶段时，应明确标注实验性、未完成点和后续建议。

## 文档要求
- 所有新增类、接口、结构体、枚举，必须使用中文 XML 文档注释。
- 所有新增的公开方法、公开属性，也必须使用中文 XML 文档注释。
- 文档不应只重复代码表面行为，而应尽量说明：
  - 这个成员是做什么的
  - 为什么这样设计
  - 输入输出的业务含义
  - 使用时的注意事项
  - 一旦某未完成的功能注释中包含规定的公开属性，返回参数，务必参考其规定的类型。
- 对于方法文档，最优先说明以下三类信息：
  - 输入参数 -> 参数本身的模式
  - 输出 / 返回 -> 返回量的模式
  - 方法内容 -> 方法内部的行为模式
- `param` 文档不应只写“这是某个参数”，还应尽量说明：
  - 该参数是配置量、运行时数据、控制信号、回调，还是上下文对象
  - 是否允许为空
  - 传入时的前置条件
  - 如果是集合、区间、快照或模型对象，应说明其组织模式
- `returns` 文档不应只写“返回成功/失败”或“返回结果”，还应尽量说明：
  - 返回值是状态标记、结果对象、中间结果，还是最终结果
  - 是否允许部分成功
  - 返回值和异常分别表达什么
- `remarks` 或补充注释应优先描述方法的行为模式，例如：
  - 该方法是校验型、构造型、映射型、回填型、查询型还是调度型
  - 该方法是否会修改对象状态
  - 该方法是否依赖外部资源
  - 成功与失败时的行为差异

## 注释要求
- 这是一个学习型项目，普通业务代码应尽量保持较高注释率，目标不低于 50%。
- 注释重点应放在以下内容：
  - 业务意图
  - 关键设计选择
  - 容易误解的细节
  - 临时写法、待重构点、未完成点
- 不鼓励机械式注释，例如“给变量赋值”“进入 if 语句”这类低信息量说明。

## 面试题要求
- 每当新增或较大幅度修改一个类时，都应补充 1 到 3 个与该类相关的面试问题。
- 面试问题应紧贴该类涉及的核心知识点，例如：
  - C# 基础语法
  - 面向对象设计
  - Attribute 与反射
  - 泛型
  - 委托、事件、异步
  - 串口通信
  - Modbus 协议
  - WPF 绑定与界面架构
- 面试问题应尽量具备复习价值，不要写成过于空泛的问题。

## 推荐写法
- 新增类时，建议包含以下内容：
  1. 中文类摘要
  2. 设计目的或职责说明
  3. 关键字段或属性说明
  4. 核心方法说明
  5. 注意事项
- 如果类较复杂，可以在类前增加“设计说明”注释块，帮助后续复盘。

## 输出与讲解风格
- 优先使用中文解释。
- 说明问题时，尽量同时说明“做了什么”和“为什么这样做”。
- 面向“学习者 + 开发者”的双重视角，不只追求功能完成，也追求知识沉淀。

## 修改代码时的偏好
- 相比炫技式写法，优先选择结构清晰、便于讲解的实现。
- 若使用反射、泛型、委托、异步、WPF 绑定等知识点，应尽量补足注释，帮助理解。
- 若代码与工业通信、寄存器映射、设备建模相关，应特别说明地址、数据类型、映射规则和边界条件。
